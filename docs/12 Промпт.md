# Промпт и оценщик — v1

> [!important] Принцип
> Промпт **собирается из чек-листа**. В коде нет ни одного названия критерия. Заменили критерий в UI → новый промпт и новая схема ответа собрались сами.
> Модель возвращает ответы и номера реплик. **Баллы считает `shared/scoring.ts`.**

> [!warning] Честная оценка
> В промпте нет ID диалогов DEV, их фраз дословно и наших ответов эталона. Примеры — обобщённые.

Связано: [[02 Чек-лист и правила оценки]] (решения D-01…D-19) · [[07 Решения (ADR)#ADR-003 Модель для оценки]] (Gemini, ошибки, лимиты) · [[06 Точность]] (версии и метрики).

## 2. Из чего собирается запрос
```
┌ системная инструкция ───────────────────────────────┐
│ 1. prompts/system.md          — одинакова всегда     │
│ 2. ЧЕК-ЛИСТ: title (версия N)                        │
│    2а. checklist.guidelines   — правила чек-листа    │
│    2б. checklist.criteria[]   — по шаблону §3        │
└──────────────────────────────────────────────────────┘
┌ сообщение пользователя ─────────────────────────────┐
│ 3. Шапка диалога + транскрипт — формат §4            │
└──────────────────────────────────────────────────────┘
+ 4. JSON-схема ответа (responseJsonSchema) — §5
```
Неизменное — впереди, транскрипт — последним.

| Часть | Меняется при замене критерия? |
|---|---|
| `prompts/system.md` | нет |
| `guidelines` | нет (если не трогали) |
| Критерии: `id`, `title`, `section`, `description`, `type`, `steps`, `step_desc`, `na_allowed`, `na_condition`, `is_gross`, **`guidance`** | **да — собираются заново** |
| Схема ответа: `id` критериев и допустимые ответы | **да — собирается заново** |

**`guidance`** (массив строк) — уточнения и наши решения D-xx по критерию. На баллы не влияет, редактируется в UI вместе с критерием. Необязательные поля (`na_condition`, `step_desc`, `guidance`) можно не заполнять — промпт соберётся и без них, только точность будет ниже.

## 3. Один критерий — шаблон
```text
КРИТЕРИЙ {{id}}. {{title}}
Секция: {{section}}
{{#if is_gross}}Это флаг грубого нарушения: "yes" — нарушение найдено, "no" — не найдено. На баллы не влияет.{{/if}}
Что оценивается: {{description}}
{{#if binary}}Ответ: "yes" (Да) или "no" (Нет){{#if na_allowed}} или "na" (N/A){{/if}}.{{/if}}
{{#if scale}}Ответ: одна ступень из {{steps}}{{#if na_allowed}} или "na" (N/A){{/if}}.
Ступени: от большей к меньшей, с текстом step_desc{{/if}}
{{#if na_allowed}}N/A разрешён ТОЛЬКО если: {{na_condition}}{{else}}N/A для этого критерия запрещён.{{/if}}
{{#if guidance}}Уточнения:
- {{каждая строка guidance}}{{/if}}
```

## 4. Транскрипт
```text
ДИАЛОГ {{conversation_id}}
Канал: {{channel}} · Язык: {{language}} · Реплик: {{N}}

[#1 КЛИЕНТ 00:00] …
[#9 СИСТЕМА 00:38] Эскалация на оператора.
[#10 ОПЕРАТОР 01:15] Здравствуйте! Меня зовут …
```
- `#N` = индекс в `transcript` + 1 — **так же нумерует UI**.
- Роли: `client` → КЛИЕНТ, `operator` → ОПЕРАТОР, `bot` → БОТ, `system` → СИСТЕМА, иное — как есть заглавными.
- Время: у чатов как в данных (`MM:SS`). У звонков (ISO-метки) — смещение от первого события в `MM:SS`.
- Переносы строк внутри реплики заменяются пробелом, остальной текст без изменений.

## 5. Схема ответа
```json
{ "items": [ {
  "criterion_id": "enum: id критериев",
  "analysis": "рассуждение по шагам (в UI не показываем, храним для разбора ошибок)",
  "answer": "enum: yes / no / na / ступени шкал строками",
  "evidence": [12, 14],
  "checked_range": [10, 16],
  "reason": "«Название — Ответ. Почему. Основание — #N.»",
  "na_reason": "только для na"
} ] }
```
- `analysis` стоит **перед** `answer`: модель сначала рассуждает, потом отвечает.
- `minItems = maxItems = числу критериев`; обязательные поля: `criterion_id`, `analysis`, `answer`, `evidence`, `reason`.
- Ступени есть в enum только от шкальных критериев.

## 6. Проверка ответа (`checkAnswer`)
| Нарушение | Что делаем |
|---|---|
| Не JSON (ответ в блоке ```json тоже принимается), нет `items` | повтор |
| Нет ответа по критерию или два ответа | повтор |
| N/A там, где запрещён; ступень не своей шкалы; yes/no у шкалы | повтор |
| Повтор тоже не прошёл | `EvaluationError` — без тихой подмены |
| Номер реплики вне диалога | номер убираем, `needs_review` с этими номерами |
| Кривой `checked_range` | убираем, `needs_review` |
| «Нет» без доказательства и без `checked_range`; «Да»/ступень без доказательства; N/A без причины; пустой `reason` | `needs_review` |

Повтор — один, в запрос добавляется список ошибок: «ПРЕДЫДУЩИЙ ОТВЕТ НЕ ПРОШЁЛ ПРОВЕРКУ: …».
`evidence` приводится к порядку по возрастанию, без повторов.

**До вызова модели** проверяется сам чек-лист (`checklistProblems`): есть критерии, `id` не пустые и не повторяются, у шкалы ≥ 2 числовые ступени, `type` = `binary` или `scale`. Сломан → понятная ошибка, запрос к Gemini не тратится. Эту же функцию Б1 может звать при сохранении чек-листа.

## 7. Голосование (`CQA_VOTES`)
- `CQA_VOTES=3` в `.env` → 3 независимых прогона, по каждому критерию ответ большинства. Ничья у шкалы — медиана; иначе — ответ первого прогона из лидеров.
- Если прогоны разошлись → `needs_review: true`, `review_reason`: «прогоны разошлись: yes×2, no×1». Проверяющий сразу видит спорные места.
- Зачем: на Gemini 3.6+ `temperature` игнорируется, ответы на спорных критериях плавают (см. [[06 Точность]] E-02).
- По умолчанию `1` (выключено): втрое больше запросов. Включать только после замера на эталоне.

## 8. Результат оценки (`EvaluationDraft`) — для Б1, Б2, Ф
| Поле | Что |
|---|---|
| `conversation_id`, `checklist_id`, `checklist_version` | что оценивали |
| `prompt_version` | `v1` |
| `model` | фактическая модель из ответа Gemini (при голосовании разные — через `+`) |
| `votes` | число прогонов |
| `usage` | `calls`, `input_tokens`, `output_tokens` (выход вместе с размышлениями) |
| `cost_usd` | 0 — бесплатный уровень |
| `duration_ms`, `created_at` | время |
| `items[]` | `criterion_id`, `analysis`, `answer` (`'yes'`/`'no'`/`'na'`/число), `evidence`, `checked_range`, `reason`, `na_reason`, `needs_review`, `review_reason` |

Баллов в результате нет: их добавляет `shared/scoring.ts` (Б2). `id` записи добавляет хранилище (Б1).

Вызов из маршрута: `await evaluateConversation(conversation, checklist)` — модель берётся из `.env` сама. Ошибки: `EvaluationError` (чек-лист или ответ модели не прошли проверку), `LlmError` (Gemini недоступен) → 502 с текстом.

## 9. Репетиция замены критерия (T+23)
1. В редакторе заменить критерий: `title`, `description`, `type`, `steps` (числа!) / `step_desc`, `na_allowed` / `na_condition`, `guidance`.
2. Сохранить → версия чек-листа +1.
3. Оценить 1 диалог → в промпте новый критерий, в схеме его `id` и ответы, старого нет. Если чек-лист сломан — ошибка сразу, без запроса к модели.
4. Итог пересчитан `scoring.ts` с новым весом.
5. Ни одной правки кода (это проверяет тест `replacing a criterion changes prompt and schema with no code change`).

npx tsx scripts/try.ts p1-ru-001 p1-kz-001
