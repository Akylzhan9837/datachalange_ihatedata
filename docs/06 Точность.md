# Точность

> [!important] Это главный критерий жюри. Улучшаем только то, что видно в метриках.

## Ground Truth (своя разметка DEV)
Файл: `data/gt/dev_gt.json`. Ключи критериев — id из чек-листа, значения: `yes` / `no` / `na` или число (ступень шкалы).
```json
{ "p1-ru-001": { "01": "yes", "02": "na", "03": "na", "04": 20, "05": "yes", "06": 10, "07": "yes", "08": "no",
                 "_note": "почему спорно" } }
```
Итог в эталон не вписываем: его считает `shared/scoring.ts` из ответов.

Правила разметки:
- Размечают двое независимо, расхождения обсуждаются → это и есть самые опасные случаи для промпта.
- Первыми: все 5 звонков, по 5 KZ и EN, все диалоги с N/A и грубыми ошибками.
- Цели: 10 диалогов к T+5, 20 к T+9 (все языки, все 5 звонков).

Инструменты (`npm run gt -- …`):
| Команда | Что делает |
|---|---|
| `plan` | порядок разметки: 20 диалогов, выбранных по структуре (звонки, закрытие чата, обрыв, идентификация, нет приветствия), RU/KZ/EN вперемешку |
| `show <id>` | диалог с номерами реплик; `--hints` показывает подсказки правил (смотреть после своей разметки) |
| `stub <id>` | заготовка записи для вставки в `dev_gt.json` |
| `check` | проверка формата эталона (N/A только где разрешён, ступень из шкалы) и прогресс по целям |

## Прогон `npm run eval`
```
npm run eval -- --label "промпт v1" [--results data/results/latest.json] [--gt data/gt/dev_gt.json]
```
Вход `--results`: `{ "meta": { "model", "prompt_version", "invalid_json", "retries", "cost_usd", "time_ms" }, "results": [ { "conversation_id", "items": [ { "criterion_id", "answer": "yes|no|na|scale", "step": 15, "reason": "…" } ] } ] }`.
Для шкального критерия значение берётся из `step`, N/A — `answer: "na"`. Отчёт печатается и пишется в `data/results/<label>.report.md`: точность по критериям, ±1 ступень, MAE итога и смещение, N/A (пропущенные и лишние), precision/recall грубых ошибок, срезы по языку и каналу, список ошибок и готовая строка для таблицы ниже.

## Метрики (`npm run eval`)
- Совпадение ответа по каждому критерию (%)
- MAE итогового балла
- Recall/precision грубых ошибок
- Доля невалидного JSON / ретраев
- Стоимость и время одной оценки

## Гипотезы ошибок модели
- [ ] Засчитывает оператору приветствие бота (01)
- [ ] Путает «Нет» и N/A (02, 03, 07)
- [ ] Ставит N/A где не разрешено (01, 05, 06)
- [ ] Шкалы 04/06 смещены вверх (модели «добрые»)
- [ ] Не замечает раскрытие данных до идентификации (03, 08)
- [ ] KZ: хуже понимает вежливость/приветствие
- [ ] Звонки: шум ASR и путаница ролей
