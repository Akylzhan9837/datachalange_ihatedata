**Говорит:** ТЛ. **Кликает:** Ф (ТЛ не трогает мышь — так быстрее и без пауз). **Б1** следит за сервером и квотой, **Б2** держит секундомер и показывает пальцами оставшиеся минуты.

> [!important] Идея выступления в одной фразе
> «Система честно оценивает любой новый диалог по чек-листу, который можно поменять на лету, и каждое решение подтверждено конкретной репликой.»

## Репетиция замены критерия (если организаторы не назвали заранее)
Тренировочная замена: **07 «Завершение» → «Предложение дальнейшей помощи»**
- Тип: Да / Нет / N/A · Вес: 5
- Описание: «Да — перед завершением оператор спросил, остались ли у клиента вопросы, или предложил помощь.»
- N/A: «Чат оборвался до возможности завершить.»
- Уточнения: «Одно прощание без вопроса о помощи — Нет.»
- Ступени шкалы, если тип «шкала», — **числами**. Сломанный чек-лист (повтор id, шкала без ступеней) оценщик отклонит сразу с понятной ошибкой, без запроса к модели.

Цель — уложиться в **60 секунд** от «Чек-листы» до начала оценки. Засекать. Репетиция стоит 1 запрос.

```bash
node -e "const g=process.argv[1];(async()=>{const s=await (await fetch('http://localhost:3000/api/sets/'+g)).json();for(const c of s.data.records){const r=await fetch('http://localhost:3000/api/evaluate',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({conversation_id:c.conversation_id,checklist_id:'cqa-full'})});const j=await r.json();console.log(c.conversation_id,r.status,j.total_score??j.error)}})()" GROUP_ID
```

## Сдача результатов (приложение к гайду, формат JSON 1.0)
Файлы в корне репозитория: `results/dev/results.json` (DEV: 60 чатов + 5 звонков) и `results/prod/results.json` (ровно 10 контрольных). На контрольный набор — **1 час до стоп-кода**, считается только то, что запушено.

```bash
npx tsx scripts/export-results.ts dev
```
```bash
npx tsx scripts/export-results.ts prod --group GROUP_ID
```
- `team_name` = `ihatedata` (по умолчанию; другое — `--team` или `TEAM_NAME` в `.env`).
- `prod`: набор скачивается из `CQA_API_URL` по `group_id` и сохраняется в `data/sets/GROUP_ID.json`. Не через `/api/sets`: тот при ошибке молча отдаёт DEV.
- Оценка → баллы через `shared/scoring.ts` → коды `contact … critical`, `true/false/null/число`, `rationale` = обоснование, `evidence_turns` = номера реплик с 1 (для «Нет» без доказательства — реплики оператора из проверенного участка).
- Готовые оценки берутся из кэша (`data/storage/export/`, та же версия чек-листа и промпта), а затем из хранилища сервера (`data/storage/evaluations.json`, та же версия чек-листа; оценки, изменённые апелляцией, не берутся). Повторный запуск тратит квоту только на недооценённые. `--force` — оценить заново.
- **DEV гнать через сервер** (запасной скрипт выше или «Оценить весь набор»), а потом `export-results.ts dev`: тогда оценки видны в UI (для вопроса жюри «покажите все грубые ошибки») и квота не тратится дважды.
- **После демо с правкой чек-листа** — `git checkout data/checklists/cqa-full.json`: редактор перезаписывает рабочий чек-лист (версия +1), и следующая выгрузка оценила бы всё заново по изменённому.
- Не удалось оценить → запись `status: "error"` с причиной, без подмены нулём. Gemini кончился → оставшиеся помечаются ошибкой сразу, без лишних запросов; запустить ещё раз позже.
- Скрипт сам проверяет формат: все ID на месте, без повторов, 8 критериев, допустимые значения, `critical_flag` = `critical`, итог 0–100 с двумя знаками. Проблемы печатает, код выхода 1.
- Несколько ключей: `GEMINI_API_KEY=ключ1,ключ2,ключ3` в `.env`, потом перезапустить сервер. Сначала лучшая модель на всех ключах по очереди, потом следующая модель; исчерпанный за сутки или неверный ключ пропускается. Ключи разных аккаунтов Google — у каждого своя квота.
- Квота: DEV — 65 запросов, это больше суточных 20 одной модели. Гнать DEV заранее, частями, после сброса квоты (~13:00 по Астане). На prod оставить ≥ 12 запросов основной модели.

## Вопросы жюри — заготовки ответов
- **«Это не заготовленные ответы?»** — «Покажу: меняю критерий и запускаю заново. У каждой оценки — версия чек-листа, версия промпта, модель и время. В коде нет ни одного критерия — промпт и схема ответа собираются из чек-листа.»
- **«Как вы мерили точность?»** — «Разметили диалоги DEV вручную и сравниваем каждый прогон: совпадение по критериям X%, ошибка итога Y баллов.» (цифры — из [[06 Точность]])
- **«Почему ответы модели стабильны?»** — «Схема ответа ограничивает значения, код проверяет смысл. На спорных местах модель может колебаться — для этого есть режим нескольких прогонов с голосованием, расхождение помечается проверяющему.»
- **«Сколько стоит одна оценка?»** — «На бесплатном уровне Gemini — $0: около 4–6 тысяч токенов на вход и 3–5 тысяч на выход вместе с размышлениями модели.»
- **«Почему облако, а не локальная модель?»** — «Точность — главный критерий; на нашем ноутбуке (6 ГБ видеопамяти) помещается только 7–8B модель, она заметно слабее на казахском и звонках. Провайдер подключается в одном модуле.»
- **«Почему звонки по транскрипту, а не по аудио?»** — «Один чек-лист и один конвейер на все каналы: поменяли критерий — работает и для чатов, и для звонков. Текст в 3–5 раз дешевле аудио на каждой оценке. Тон голоса текст не передаёт — поэтому у доказательства таймкод и кнопка записи: проверяющий слушает нужные секунды при апелляции. Следующий шаг — аудио только для спорных критериев у помеченных звонков.»
- **«Как встроить в Dynamics 365?»** — «Интерфейс — статический HTML/CSS/JS с относительными путями, адрес бэкенда задаётся параметром.»
