# Данные и API

## API организаторов
GET, параметр `group_id` (DEV сейчас; контрольный дадут на T+23). Ссылка (Power Automate, с ключом `sig`) — в `.env` → `CQA_API_URL` (в Git не попадает). Взять из кнопки «Открыть GET для DEV» в гайде.

> [!warning] Из браузера — CORS. Ходим только через свой бэкенд (план: `GET /api/sets/:group_id`). `group_id` — поле в шапке UI.

Копия DEV уже скачана: `data/sets/DEV.json` (65 диалогов, 2026-11-07) — по ней размечаем эталон. План: бэкенд обновляет такую копию при каждом удачном запросе и отдаёт её, если API упал.

## Записи звонков
`audio_url` — это **HTML-страница плеера**, внутри `<source src>` с подписанной ссылкой на mp3 (живёт ~1 час). План: бэкенд вытаскивает её (`GET /api/audio?url=` → `{src}`), наш `<audio>` перематывается к реплике. Проверено вручную: mp3 играется в браузере, перемотка работает.
Смещение = время реплики − время первого события. В записи бывают паузы («Запись приостановлена») → возможен сдвиг на секунды (p4-ru-003: запись 393 с, транскрипт 399 с).

## Формат
```json
{ "error": "", "isSuccess": true, "data": {
  "dataset_group_id": "DEV", "total_records": 65,
  "records": [{ "conversation_id": "p1-ru-001", "channel": "agent chat",
    "language": "RU", "transcript": [{"timestamp":"00:02","speaker":"operator","text":"..."}],
    "audio_url": null }] } }
```
- `speaker`: `client` / `operator` / `bot` / `system`
- `timestamp`: чаты — `MM:SS`; звонки — ISO 8601 с TZ. **Сохранять исходные.**
- `audio_url`: null у чатов, ссылка у звонков.

## Наблюдения
- Чат начинается с бота (AIM), затем системное «Эскалация на оператора» → оператор. Критерий 01 считаем по первой реплике **оператора**.
- В звонках есть системные события о смене языка (kk-KZ → ru-RU) и шум ASR в транскрипте («Салими цбе Фридом брокер…») — модель должна быть устойчива к ошибкам распознавания.
- Звонки: роли оператора/клиента в транскрипте нужно проверить вручную на всех 5.
