## ADR-003 Модель для оценки
- **Статус:** ✅ принято ТЛ 2026-11-07 — **Gemini API (облако, бесплатный уровень)**, по умолчанию `gemini-3.5-flash` с запасными моделями. Сравнение с `gemini-3.8-flash` — когда будет эталон (`npm run eval`).

> [!important] Итог
> - **Основная:** Gemini API, бесплатный уровень, ключ из Google AI Studio (`GEMINI_API_KEY` в `.env`, в Git не попадает). Стоимость одной оценки — $0.
> - **Локальная (Ollama на ноутбуке ТЛ)** — только если: (а) упрёмся в лимиты бесплатного уровня (проверяем к T+9 на прогоне DEV) Запрет на звонки снят: организаторы разрешили отправлять реальные звонки в бесплатный Gemini (Q-9, 2026-11-07). Иначе не делаем.
> - **Claude API** — не используем (платный). Таблица ниже остаётся как справка, если появятся кредиты.
- **Контекст:** главный критерий — точность. Нужны RU/KZ/EN, строгий JSON, 65 диалогов DEV + 10 контрольных, стоимость одной оценки в README.

### Gemini — как вызываем (P-03, сделано в `server/llm.ts`)
> [!success] Проверено на нашем ключе и по документации Google, 2026-11-07
> - **Доступность на бесплатном уровне:** `gemini-3.1-pro`, `gemini-4-argon` — лимит **0**, недоступны. `gemini-3.5-flash` (API отвечает версией `gemini-3.6-flash`), `gemini-3.8-flash`, `gemini-2.5-flash` — работают. `3.8-flash` и `3.7-flash` бывают перегружены (503 «high demand»).
> - **По умолчанию** список `gemini-3.5-flash → gemini-3.8-flash → gemini-2.5-flash`. Свой список — `GEMINI_MODEL=a,b,c` в `.env` (для замера точности — одна модель). Фактическая модель пишется в `model` результата.
> - **Ошибки:** 503 / 5xx / 408 и обрыв сети — до 3 попыток с паузой 2 с, 4 с (+ случайная добавка до 1 с), затем следующая модель. 429: если Google просит подождать не больше 60 с (`retryDelay` в ответе) — ждём и повторяем ту же модель; если дольше (дневной лимит) — сразу следующая модель. 400 / 401 / 403 / 404 — стоп с текстом ошибки.
> - **Ключ** уходит заголовком `x-goog-api-key`, в URL его нет — не попадёт в логи и тексты ошибок.
> - **`temperature`:** на Gemini 3.6+ параметр устарел и **игнорируется**; для более ранних Gemini 3 Google советует оставлять значение по умолчанию (иначе хуже рассуждения). Поэтому `temperature: 0` передаём только моделям `gemini-1.x / 2.x`. Следствие: на спорных критериях ответ Gemini 3 может меняться от запуска к запуску (замер: один и тот же чат, критерий 05 — Нет / Да / Нет / Нет).
> - **Голосование:** `CQA_VOTES=3` — 3 прогона, ответ большинства (у шкалы при ничьей — медиана), расхождение прогонов → `needs_review` с причиной «прогоны разошлись». По умолчанию выключено — втрое больше запросов. Включать по результату замера на эталоне.
> - **Размышления:** `GEMINI_THINKING_LEVEL` = `low` / `medium` / `high` (по умолчанию у 3.6 и 3.8-flash — `medium`). `minimal` у 3.8-flash нет — не ставить. Моделям 2.x уровень не передаётся.
> - **Строгий JSON:** `responseJsonSchema` в `generateContent`, схема собирается из чек-листа: `criterion_id` — enum id критериев, `answer` — enum допустимых значений, `minItems = maxItems = число критериев`. Работает на 3.6, 3.8 и 2.5-flash (проверено вживую). Сверх схемы `server/evaluate.ts` проверяет смысл: N/A только где разрешён, ступень своей шкалы, номера реплик существуют → при нарушении один повтор с текстом ошибки → иначе ошибка, без тихой подмены.
> - **Без SDK:** REST через `fetch`, новой зависимости нет.
> - **Лимиты:** числа RPM/RPD Google показывает только в AI Studio, в документации их нет — посмотреть и вписать сюда.
> - **Расход** на один чат: ~4 000 токенов на вход, 3 000–5 000 на выход (вместе с размышлениями), 15–35 с.

- **Бюджет запросов:** DEV 65 + ~20 прогонов × 20 диалогов эталона + 10 контрольных + демо ≈ **500 запросов** за хакатон (+ повторы при ошибках; ×3 при голосовании). Если дневного лимита не хватает — прогоны точности на части эталона, контрольный набор считать заранее, запасной — Ollama.
- **Параллельность:** не больше, чем позволяет лимит в минуту, — очередь в пакетной оценке (Б1, P-11). Минутный 429 `llm.ts` переживает сам (ждёт `retryDelay`).
- Каждый вызов пишет счётчик токенов из ответа → `usage` в результате; `cost_usd` = 0 на бесплатном уровне.
- **Данные:** на бесплатном уровне Google может использовать отправленное для улучшения своих продуктов. Синтетические чаты — ок. Реальные звонки — **разрешено организаторами** (Q-9, 2026-11-07).

### Справка: Claude API, если появятся кредиты
- SDK `@anthropic-ai/sdk` (проект на TypeScript).
- Строгий JSON — **structured outputs** `output_config: { format: … }` со схемой, собранной из чек-листа: `criterion_id` — enum id критериев, `answer` — enum допустимых значений.
- **`temperature` не передаём** — на текущем API это ошибка 400. Стабильность даёт схема, уровень `effort` и, если нужно, несколько прогонов с голосованием.
- Размышления: у Opus 5.5 их нельзя выключить, управляем `output_config.effort`. Его значение по умолчанию — `medium`; сравнить `medium` и `high` на калибровке.
- Предзаполнение ответа (prefill) не работает — только схема и инструкции.
- Проверять `stop_reason`: при `refusal` — повтор или `needs_review`. Включить серверный fallback (`fallbacks: "default"`).
- Кэш промпта: постоянная часть (правила + чек-лист) идёт первой и кэшируется; транскрипт — после. Проверять `usage.cache_read_input_tokens`.
- Каждый вызов пишет `usage` (входные и выходные токены) → `cost_usd` в результате.
- Прогоны точности без спешки можно гнать через Message Batches — на 50% дешевле.

### Открытые вопросы ТЛ (история обсуждения)
- **Ноутбук ТЛ (проверено 2026-11-07):** NVIDIA RTX 4050 Laptop, 6 ГБ видеопамяти, 16 ГБ RAM, Ollama не установлен. Целиком в GPU помещается модель 7–8B (квантованная); 14B уже частично уйдёт в RAM и будет медленной. Проверить железо остальных троих.
- Полностью локально — ключ API не нужен. Выбор зависит от железа: есть ли ноутбук с GPU (≈8 ГБ видеопамяти для 7–8B, ≈16–24 ГБ для 14B+)?
- Если GPU сильная → основная локальная (кандидаты: Qwen 14B; для казахского проверить KazLLM от ISSAI в Ollama), облако — запасной вариант при наличии ключа.
- Если GPU слабая или нет → основная облачная, нужен API-ключ Anthropic и бюджет (~$30 на весь хакатон).
- Довод за локальную: организаторы сохраняют в топ-50 решения на локальных LLM — конкуренция внутри категории может быть ниже. Довод против: точность — главный критерий, а локальные модели слабее на казахском и звонках.

### Последствия
- В README: провайдер и модель Gemini, бесплатный уровень, число вызовов на одну оценку, стоимость $0 (и сколько стоило бы на платном уровне — по реальным `usage`).
- Ключ: `GEMINI_API_KEY` только в `.env`. Если ключ один на команду — у ТЛ, остальные работают на тестовых ответах до M1.
- Смена модели — только через прогон `npm run eval` и запись в [[06 Точность]].

## ADR-001 LLM не считает баллы
- **Контекст:** итог должен строго следовать формуле чек-листа (N/A, веса, округление).
- **Решение:** LLM возвращает ответы и доказательства, баллы считает код с тестами.
- **Альтернативы:** считать в LLM — арифметические ошибки, невоспроизводимо.
- **Последствия:** формула проверяема, пересчёт после апелляции мгновенный и без LLM.

## ADR-002 TypeScript + Tailwind для UI
- **Контекст:** задание требует «HTML, CSS и JavaScript» с адаптацией под Dynamics 365.
- **Решение:** пишем на TS + Tailwind, сдаём собранный статический HTML/CSS/JS. В README прямо указать: «исходники TS, результат сборки — чистый HTML/CSS/JS в `dist/`».
- **Альтернативы:** чистый JS — меньше риска формальных претензий, но больше багов.
- **Последствия:** уточнить у организаторов ([[09 Вопросы организаторам]]).
