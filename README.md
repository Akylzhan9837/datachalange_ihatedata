# CQA — оценка качества диалогов поддержки

Команда **ihatedata** · Freedom Broker CQA Hackathon

Система оценивает работу оператора в чате или звонке по настраиваемому чек-листу. По каждому критерию она показывает ответ, баллы, вес, обоснование и реплику-доказательство. Оценку можно оспорить, проверяющий принимает решение, итог пересчитывается.

- **Модель не считает баллы.** Она возвращает ответ по критерию и номера реплик, а итог, веса, N/A и секции считает код (`shared/scoring.ts`, покрыт тестами).
- **Промпт собирается из чек-листа.** В коде нет ни одного критерия: изменённый или новый критерий работает без правки кода.
- **Каждое «Да» подтверждено репликой.** Ответ модели проверяется кодом; если он не проходит проверку или модель не уверена, критерий помечается ⚠ для проверяющего, без тихой подмены.

## Быстрый старт

1. Установка зависимостей:
```bash
npm install
```

2. Настройка переменных окружения:
```bash
cp .env.example .env
```
В `.env` заполнить:
- `GEMINI_API_KEY` — ключ Google AI Studio (aistudio.google.com, бесплатный уровень). Можно несколько ключей через запятую: при исчерпании суточной квоты система переходит к следующему.
- `CQA_API_URL` — ссылка GET организаторов (кнопка «Открыть GET для DEV» в гайде).

3. Запуск:
```bash
npm run dev
```

4. Открыть интерфейс: **http://localhost:3000**

Интерфейс — статические HTML/CSS/JS в `frontend/` с относительными путями, адрес бэкенда задаётся параметром `?api=` (по умолчанию `http://localhost:3000/api`). Так его можно встроить как HTML-компонент Dynamics 365.

## Как пользоваться

1. Слева — диалоги набора с фильтрами: тип (чат / звонок), язык (RU / KZ / EN), поиск, **«Только грубые ошибки»**. Другой набор — поле «Набор данных» внизу (`group_id`).
2. Выбрать чек-лист и нажать **«Оценить»**. **«Перезапустить»** — новая оценка без кэша. **«Оценить весь набор»** — все диалоги по очереди.
3. В карточке: итог и секции, по каждому критерию ответ, баллы, вес после перераспределения N/A, обоснование, кнопки «Реплика #N» (переход к сообщению), проверенный участок для «Нет», причина N/A. Для звонков — ссылка на запись.
4. **Апелляция:** «Оспорить» у критерия → комментарий. **Режим проверяющего** → подтвердить или изменить оценку с причиной → итог пересчитывается, в карточке видны исходная оценка, решение и финальный результат.
5. **Чек-лист:** «Редактировать» — добавить, изменить или удалить критерий, вес, тип ответа (Да/Нет или шкала), доступность N/A, флаг грубой ошибки. Сохранение создаёт новую версию; оценки хранят версию чек-листа, по которой сделаны.

## Модель и стоимость

| | |
|---|---|
| Модель | Gemini API (`external_api`): `gemini-3.5-flash`, запасные `gemini-3.8-flash` и `gemini-2.5-flash` |
| Вызовов на оценку | 1 (повтор только при невалидном ответе) |
| Токены на оценку | ≈ 4–6 тыс. на вход, 3–5 тыс. на выход вместе с размышлениями модели |
| Время | 15–40 секунд на диалог |
| Стоимость | $0 на бесплатном уровне Gemini |

Звонки оцениваются по транскрипту тем же конвейером; запись — для проверяющего при апелляции. Обоснование: `docs/07 Решения (ADR).md`, ADR-004.

## Известные ограничения

- На спорных критериях (тон, полнота консультации) повторная оценка может сдвинуться на ступень. Для таких случаев есть режим голосования `CQA_VOTES=3` в `.env` (три прогона, ответ большинства, расхождение помечается ⚠).
- Бесплатный уровень Gemini — около 20 запросов в сутки на модель на ключ. Поэтому поддерживается несколько ключей.
- Тон голоса по транскрипту не виден; для этого проверяющий слушает запись.

## API Endpoints

- `GET /api/health` — проверка работоспособности сервиса
- `GET /api/sets/:group_id` — получение набора диалогов (с автоматическим кэшированием)
- `GET /api/checklists` — список доступных чек-листов
- `GET /api/checklists/:id` — получение чек-листа по идентификатору
- `POST /api/checklists` — сохранение новой версии чек-листа
- `GET /api/audio?url=...` — извлечение прямой ссылки на аудиопоток (только для `*.api.powerplatform.com`)
- `POST /api/evaluate` — запуск оценки диалога через LLM
  - Body: `{ "conversation_id": "p1-ru-001", "checklist_id": "cqa-full", "force": false }`
  - Response: объект `EvaluationResult` с рассчитанными `total_score`, `section_scores`, `gross_violation`, флагами `rule_flags` и `points` по каждому критерию.
  - Кэш по паре (диалог + версия чек-листа), при `force: true` переоценивает заново.
- `GET /api/evaluations` — список результатов оценок
- `GET /api/evaluations/:id` — результат оценки по идентификатору
- `GET /api/evaluations/by-conversation/:conversation_id` — результат оценки по идентификатору диалога
- `POST /api/appeals` — регистрация апелляции
  - Body: `{ "evaluation_id": "...", "criterion_id": "01", "comment": "..." }`
- `GET /api/appeals` — список зарегистрированных апелляций (поддерживает `?evaluation_id=...`)
- `POST /api/appeals/:id/decide` — принятие решения по апелляции
  - Body: `{ "status": "accepted" | "rejected", "reviewer_answer": "yes", "reviewer_reason": "..." }`
  - При `accepted` автоматически пересчитывает итоговый балл `total_score` и баллы по секциям.
