# RULES — правила команды CQA

Обязательны для всех: для людей и для AI-ассистентов (Claude Code, Cursor и т.д.).
Сомневаешься — спроси ТЛ. Правило нарушается только с согласия ТЛ.

---

## 1. Приоритеты
Когда не знаешь, что делать первым, выбирай сверху вниз:
1. **Точность против эталона** — главный критерий жюри.
2. **Обязательные функции кейса** — список R-01…R-20 в `docs/01 Задание.md`.
3. **Удобство интерфейса.**
4. **Дополнительные фичи** — только после 1–3.

Свободная минута → помоги Б2 с разметкой эталона.

## 2. Роли и файлы
Каждый работает **только в своих файлах**. Чужой файл — сначала напиши владельцу.

| Роль | Кто | Свои файлы |
|---|---|---|
| ТЛ — тимлид + LLM | Арлан | `server/evaluate.ts`, `server/llm.ts`, `server/results.ts`, `prompts/`, `scripts/export-results.ts`, `RULES.md` |
| Б1 — бэкенд «данные и процессы» | ____ | `server/index.ts`, `server/store.ts`, `README.md` |
| Б2 — бэкенд «точность» | ____ | `shared/scoring.ts`, `data/gt/`, `scripts/eval.ts`, `server/rules.ts` |
| Ф — фронтенд | ____ | `web/` |

**Общие файлы** — менять только с предупреждением в чате команды:
`data/checklists/*.json`, `package.json`, `tsconfig.json`, `vite.config.ts`.
Новая npm-зависимость — только с согласия ТЛ.

Подробно, кто что делает и к какому часу: `docs/11 Команда.md`.

## 3. Честная оценка (жюри это проверяет)
- **Никаких заготовленных ответов.** Нельзя хардкодить оценки, класть ответы эталона в код или в промпт, подменять результат готовым файлом.
- **Промпт строится из текущего чек-листа.** Новый или изменённый критерий должен работать без правки кода.
- **Баллы считает только `shared/scoring.ts`.** Модель возвращает ответы по критериям и номера реплик-доказательств, итог никогда не считает.
- Каждый результат хранит версию чек-листа, модель и время. Кэш — только по паре «диалог + версия чек-листа», с кнопкой «перезапустить».

## 4. Точность
- Промпт меняет **только ТЛ**. Остальные присылают ему ошибки: «диалог · критерий · что не так».
- Любое изменение промпта или модели → прогон `npm run eval` → строка в `docs/06 Точность.md`. Нет цифр — нет изменения.
- Правим **общие правила**, а не подгоняем под один диалог.
- Эталон (`data/gt/`) размечают люди. Модель свою разметку эталоном не делает.

## 5. Код
- TypeScript. UI собирается в чистые HTML/CSS/JS (`dist/`), пути относительные — нужно для Dynamics 365.
- Минимум кода: сначала то, что уже есть в проекте, потом стандартная библиотека, и только потом новое.
- Проверяй всё, что приходит снаружи: данные API, ответ модели, тело запросов.
- Текст из диалогов в HTML — только через экранирование (одна функция `esc()` на весь UI).
- **Секреты только в `.env`.** Ссылки API, ключи моделей и токены не попадают в Git, в чат и в документацию.

## 6. Git
- Перед работой: `git pull --rebase`.
- Перед коммитом: `npm test` и `npm run typecheck` — оба зелёные.
- Коммиты маленькие, сообщение — `[роль] что сделано`, например: `[Б1] хранение результатов оценки`.
- `main` всегда запускается. Сломал — чини сразу или откатывай свой коммит.
- Никаких `git push --force` и никаких правок чужой истории.

## 7. Готово — это когда
1. Работает: запустил и проверил руками (или есть тест).
2. `npm test` и `npm run typecheck` зелёные.
3. Статус задачи обновлён в `docs/05 План.md`, требование — в `docs/01 Задание.md`.
4. Значимое решение записано в `docs/07 Решения (ADR).md`.
5. Закоммичено и запушено.

## 8. Общение
- Синк каждые **3 часа**, 10 минут: сделал / блокирует / метрики.
- Застрял больше чем на **20 минут** — пиши в чат, не сиди молча.
- Меняешь формат данных между частями (результат оценки, API) — сначала договорись с тем, кто их использует.

## 10. Экономия лимитов и бюджета
- **Кэширование:** пара «диалог + версия чек-листа» оценивается через LLM ровно один раз. Повторный запрос берётся из кэша. Запрос к LLM уходит только при новой версии чек-листа или ручном нажатии «Переоценить».
- **Ступенчатые прогоны:** запрещено запускать оценку всех 65 диалогов на сыром промпте. Схема отладки: 1 диалог ➔ 3 диалога калибровки ➔ 10–20 диалогов эталона (GT). Полный прогон — только перед контрольными точками.
- **Ограничение параллелизма:** пакетная оценка шлёт не более 3–5 параллельных запросов к API LLM.
- **Ретраи с backoff:** при ошибках 429 (Too Many Requests) выдерживается пауза с экспоненциальным откатом (1s, 2s, 4s).
- **Компактный контекст:** модель получает только реплики `[#ID speaker timestamp] текст`, без лишнего JSON-мусора.
- **Бюджет:** каждая оценка сохраняет расход токенов и расчетную стоимость.

## 11. Для AI-ассистентов
Если ты AI и работаешь в этом репозитории:
1. Перед работой прочитай этот файл и `docs/00 Home.md`. Требования бери из `docs/01 Задание.md` и PDF в `inputs/`, ничего не выдумывай.
2. Спроси или определи, чью роль ты выполняешь, и меняй только её файлы. Общие файлы — только с явного согласия человека.
3. Делай минимальное изменение, которое полностью решает задачу.
4. Перед тем как сказать «готово»: запусти `npm test` и `npm run typecheck`, честно напиши, что проверено, а что нет.
5. Обновляй документацию в `docs/` в том же шаге, что и код.
6. Не коммить и не пушь без просьбы человека. Никогда не коммить `.env`.
7. Пиши по-русски, коротко: сначала результат, потом детали.
8. Береги контекст: не читай целиком большие датасеты (`DEV.json`), читай диалоги точечно по ID.
